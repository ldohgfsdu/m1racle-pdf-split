## 四、产物字节差异的解释（不是内容差异）

21 对 `L-*` / `S-*` 产物体积完全相同但 sha256 全部不同。实测原因：**trailer 里的 `/ID` 每次保存都重新生成**。

```
L-p001-020.pdf  /ID [<99CCFC8D27563B3D28A912D7B7573267> <99CCFC8D…>]
S-p001-020.pdf  /ID [<2ADD0E3BC74CDDF667B5F9AB7E01DD2C> <2ADD0E3B…>]
```

两文件均无 `/CreationDate`、`/ModDate`。因此「字节不同」不能推出「内容不同」，页级语义比对才是有效口径。

## 六、悬空资源引用的真相（修正此前结论）

此前文档写「对象 3095 / 3106 / 3148 被页面 3093 / 3104 / 3146 引用，这 3 页本就缺图」。实测把这个说法收敛为：

1. 源文件里确实存在 **3 处**悬空引用，二进制直扫可定位：
   - obj 3093（/Page）→ `/KSPX4 3095 0 R`
   - obj 3104（/Page）→ `/KSPX6 3106 0 R`
   - obj 3146（/Page）→ `/KSPX1 3148 0 R`
2. 但**只有 obj 3146 在活页树里**（对应第 15 页）。验证台遍历 420 页只报出 **1 条**不可解析条目：
   `obj=3148 XObject/KSPX1 状态=NULL 引用页=[15] Do实际绘制页=[]`
3. `3093` / `3104` 未被页树引用，属孤立页对象；它们身上的悬空引用不会被任何页面渲染到。
4. 第 15 页实际绘制的是同页另一个**存在**的对象（poppler `pdfimages` 显示该页图像 `object ID 3151`，非 3148），且内容流里没有 `KSPX1 Do`。
5. 因此：**没有任何页面缺图**。此前「3 页缺图」的判断是把「文件里存在悬空引用」误推成「页面显示缺内容」，属越界结论。
