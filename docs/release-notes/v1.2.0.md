# M1racle PDF Split v1.2.0

按页区间 / 章节 / 每份页数拆 PDF 的安卓小工具。这一版把 1.1.1 的快速加载收紧：结构看不准、或页面内容可能被静默丢掉时，不再走严格解析。

一句话结论：**988 MB / 420 页教材仍走快速路径，加载 3.0 秒；21/21 段拆分成功，产物总字节与 1.1.1 相同。内容流数组里坏掉的那一项不再被悄悄丢掉。**

## 这一版改了什么

1.1.1 已经能在这本教材上走快速路径。随后的真机矩阵说明，有几类文件会被误判成「可以严格解析」，页面实际少画内容。1.2.0 把这些路径改成失败即回退。

| 情形 | 现在的判定 |
| --- | --- |
| 页树、内容流数组中的任意一项、已声明的资源字典解析失败 | 回退到兼容解析 |
| 坏引用无法确认未被绘制（内容流截断、`Do` 配不平、嵌套 Form 过深） | 回退 |
| XObject 坏引用，且完整绘制扫描确认没人用它 | 保留快速路径，只记 `softMiss` |
| 交叉引用扫描不可信（认不出、没查完、有未验证条目、增量链不完整、加密、混合 `/XRefStm`） | 直接兼容解析，不再先试严格 |

核心修复：页面 `/Contents` 是数组时，解析失败的流不再被 `mapNotNull` 丢掉。真机样本 `11-content-array-broken` 现在回退，原因是「第 2 个内容流无法解析」；健康的双流样本仍走严格解析。

拆分算法没有改。教材产物总字节 **1,030,595,782 B**，与 1.1.1、rc2、rc3 一致。

## 真机（Xiaomi 25098PN5AC / Android 16，rc3 包复测）

| 判定 | 样本 |
| --- | --- |
| 严格 | 01 正常、12 双流正常、10 反向对照（`softMiss=1`） |
| 兼容 | 02 大内容流尾部、03 `#xx` 转义、04 嵌套 Form、05 未配对 `Do`、06 xref 破坏、07 增量更新、08 对象流、11 内容流数组 |

教材：`loadMs=2995`，`softMiss=1`，拆分 `21/21`，`totalMs=7620`。

25,000 个对象的健康文件会被新否决打到兼容解析，`loadMs=294`。慢几十秒只出现在交叉引用有坏记录、触发暴力重扫时。这条否决不需要放宽。

单测 **80 / 0 / 0 / 0**。`FastPathGuardTest` 18 例。

## 已知限制

- 加密 PDF 仍不支持打开。扫描器见到 `/Encrypt` 会否决快速路径。合成加密样本进不了系统文档选择器，所以没有界面级投喂记录。
- 结构提示只在「偏移为 0 的交叉引用」时出现。其他原因的回退没有单独解释。
- 拆分产物整包 SHA-256 不可复现（保存时写入随机 trailer `/ID`）。比较产物用页级指纹或独立解析器，不用整包哈希。
