## 1. 现有 UI/UX 问题清单

### P0 — 会让用户做出错误判断或拿到错误结果

**P0-1　「无文字层」与「无书签」被混为一谈，会误导用户放弃一条可用路径**

现状：点「识别章节」失败后提示「这本书没有文字层（纯图片扫描件），读不出标题」。用户看到这句话，会认为这个 PDF 什么自动方式都用不了。

事实：**书签和文字层是两套独立的数据**。扫描件（无文字层）完全可能有完整书签，此时「目录」按钮照样能读出章节。当前两个按钮并列且互不提示，用户没有任何线索判断自己属于哪种情况。

影响：贺银成那本 420 页 139 MB 的 PDF 正处在这个岔口上。若它有书签，本来可以一键按目录拆；现在会被一句提示劝退，退回手动填页码。

**P0-2　三种拆分方式挤在同一块区域，没有互斥的语义**

现状：「页码与名称」卡片里同时放着粘贴框、每份页数输入、生成按钮、目录按钮、识别按钮。用户无法从界面上判断「我现在用的是哪一种方式」，也不知道填了 A 会不会让 B 失效（实际是：`rangeText` 是唯一真源，点目录/识别/生成都会覆盖它）。

**P0-3　重叠、漏页、名称冲突不进入预览，错误全有或全无**

现状核查：
- 解析器**允许区间重叠**（`parseBlock` 只校验越界，不校验重叠），同一页会被写进两个文件，界面无任何提示。
- **未覆盖页无提示**：填 `1-100` 和 `200-300`，中间 101-199 凭空消失，界面显示「2 个文件」，用户以为拆完了。
- **名称冲突静默处理**：`uniqueName()` 自动加 `_2` 后缀，界面上看不到，输出文件名和用户输入的不一致。
- 任何一行出错（如某段越界），整个 `parts` 被清空，输入框下方红字只有一句概括，**不指出是第几行**。

**P0-4　禁用状态不给原因**

「开始拆分」按钮变灰时，界面上没有任何文字说明缺什么。用户需要自己猜是没选目录、还是规则没填、还是名称重名。

### P1 — 影响效率与信任

**P1-1　文件大小缺失**。139 MB 和 2 MB 的拆分手感完全不同，用户无法预估等待时间，也没有依据判断深度校验该不该开。

**P1-2　密码保护与文件损坏共用一句提示**。「读不出页数。文件可能已加密或损坏。」——加密的 PDF 有解，损坏的没有，两者应分流。

**P1-3　部分失败不可用**。当前引擎是 `coroutineScope` + `async`，任一任务抛异常会取消其余全部并从目录删除已写文件（全有或全无）。20 个文件拆到第 17 个失败，前 16 个也一起没了。

**P1-4　退出即丢全部输入**。无 ViewModel、无 `SavedStateHandle`，仅在 Manifest 声明了 `configChanges`。进程被系统回收后回来，页码、命名、输出目录全部重来。

**P1-5　深度校验的描述过度承诺**。现文案「落盘后再逐页比对内容，慢一些但最保险」，「最保险」是绝对化表述。

**P1-6　长文件名无法查看完整名称**。`TextOverflow.Ellipsis` 截断后没有展开入口。

### P2 — 视觉与秩序

**P2-1**　`01/02/03/04` 步骤编号纯装饰，拆分是单一表单不是流程，编号制造了不存在的先后依赖。
**P2-2**　绿色面积过大：主按钮、进度条、页码标签、卡片描边、选中芯片、数字高亮全用同一绿，主次不分。
**P2-3**　卡片套卡片（外部卡片 + 内部输入框 + 内部标签），三层圆角叠加。
**P2-4**　并发数（1/2/3/4/6）暴露在主界面，普通用户不理解这个数字的代价，也无从判断选几。
**P2-5**　「均分」这个按钮名与「每份页数」是两件事却挤在一行，用户以为填了页数就直接拆。

| `split/PdfOutlineReader.kt` | 136 | 书签读取、范围计算 |
| 测试 3 个文件 | — | 19 个 JVM 用例 |

### 2.2 状态管理现状

全部状态是 Composable 内的 `remember { mutableStateOf(...) }`：

```
source, rangeText, parts, planError, planWarnings, planSummary,
outputTreeUri, outputLabel, chunkSize, deepVerify, concurrency,
ui(running/headline/detail/fraction/error/outputs/tasks...),
loadingSource, readingOutline, detecting, detectProgress, outlineNotice, runJob
```

问题：
- 18 个独立状态变量，**没有单一真源**，`rangeText` 是隐式的真源（改它就重置 `parts`，但改名只改 `parts` 不改 `rangeText`，二者可以短暂不一致）。
- 校验分散在 `LaunchedEffect`、`remember(parts)`、`canRun` 三处计算。
- 无 `SavedStateHandle`，进程重建即丢失。

### 2.3 拆分引擎现状（保持不变的部分）

- 并发模型：N 个 worker 抢 `AtomicInteger` 任务队列，每个 worker 独占一个 `PDDocument`。
- 写入路径：`PDDocument.save(OutputStream)` 直接流式写入 SAF 文档，不落临时文件。
- 校验：内存中对刚构建的文档比对页数/几何（零 IO）；开启深度校验时才落盘回读并逐页比对内容哈希。
- 取消：`coroutineScope` 取消子任务，`finally` 删除已创建的 SAF 文档。
- 失败：全有或全无（见 P1-3）。

**本次不修改这些算法**，只改它的调用方式与结果呈现。

### 2.4 解析能力现状（必须保留，不可退化）

`PageRangeParser.parseBlock` 已支持：
1. 纯页码列 `71-86`
2. 单页 `5`
3. 行内「页码在前」`71-86 心肺听诊`
4. 行内「名称在前」`心肺听诊 71-86`
5. **两列分列粘贴**（页码列 + 名称列），按序配对
6. 数量不等时**拒绝配对**并出警告（第五轮修的错误静默）
7. 名称按 UTF-8 字节截断（170 B），避免超出文件系统 255 B 上限

重构 UI 时这 7 条能力必须逐条保留，且要有测试守住。

## 4. 交互状态与状态转换设计

### 4.1 单一真源

```
SplitUiState
├─ source: SourceInfo?            (uri, name, pageCount, sizeBytes, hasOutline)
├─ mode: SplitMode                (PAGES | FIXED_SIZE | OUTLINE)
├─ rule: RuleState                (各模式独立的输入与解析结果)
├─ preview: PreviewState          (files, covered, gaps, conflicts, errors)
├─ output: OutputState            (treeUri, label, deepVerify)
├─ advanced: AdvancedState        (concurrency: Auto | Manual(n))
└─ run: RunState                  (Idle | Running | Done | Partial | Failed | Cancelled)
```

`preview` 由 `rule` 纯函数推导（可单测），UI 不再各自计算。

### 4.2 状态矩阵（覆盖任务书 §5 全部 15 项）

| # | 状态 | 主按钮 | 界面反馈 |
|---|---|---|---|
| 1 | 未选 PDF | 禁用 | 空态引导「选择要拆分的 PDF」 |
| 2 | 已选 PDF，规则为空 | 禁用 | 规则区自动聚焦输入框 |
| 3 | 规则合法 | 可用* | 预览显示文件数与覆盖情况 |
| 4 | 未选输出目录 | 禁用 | 按钮下方「请先选择输出目录」 |
| 5 | 页码超出范围 | 禁用 | **对应行**标红 + 行内提示「超出 420 页」 |
| 6 | 区间重叠 | 可用 | 预览黄条「第 3、7 行重叠于 150-160 页，同一页会进入两个文件」 |
| 7 | 文件名重复 | 可用 | 预览提示「2 个名称重复，将自动加 _2」 |
| 8 | 大量章节（>20） | 可用 | 预览默认摘要，展开后限高滚动 |

| 12 | 正在拆分 | 「取消」 | 底部百分比 + 当前任务行；**再次点击不会重入**（按钮已切换为取消） |
| 13 | 部分失败 | 可用（重试失败项） | 结果页「成功 16 / 失败 4」，失败项列出原因，**已成功的保留** |
| 14 | 全部成功 | 可用（再拆一次） | 「已生成 8 个 PDF」+ 打开目录入口 |
| 15 | 用户取消 | 可用 | 「已取消，写入中的文件已清理」 |

### 4.3 关键转换

```
Idle --选文件--> SourceLoaded --填规则--> RuleParsed
RuleParsed --选目录--> Ready --开始--> Running
Running --完成--> Done | Partial | Failed
Running --取消--> Cancelled --可回到--> Ready
任意 --退出--> SavedState（Running 除外）
```

## 5. 三种模式的具体设计

### 模式一：指定页码（默认）

```
┌ 粘贴区（等宽字体，6 行起）───────────────┐
│ 71-86 CH01_心肺听诊                     │
│ 87-91 CH02_普通X线影像诊断               │
└──────────────────────────────────────────┘
  支持：页码列 + 名称列分列粘贴、行内两种顺序
  解析后显示：已识别 12 段 · 配对 12 个名称 · 剩 9 个未用
```

- 保留全部 7 条解析能力（§2.4）。
- 解析结果**逐行可见**（预览区展开即是行表），不做静默配对。
- 错误定位到行：输入框下方只列前 3 条错误，其余折叠为「还有 5 条」。

### 模式二：固定页数

```
每份 [ 50 ] 页  →  将生成 9 个文件（最后一个 20 页）
```

- **不提供「均分 N 份」**。理由：任务书要求两者不得混淆，而「均分 N 份」与「每份 N 页」在 90% 场景下等价，多一个概念多一次误解。若确需，实现为固定页数模式下的次级选项（单选：「按页数切」/「按份数切」），不在本次范围，等明确需求再加。
- 数量在输入时实时计算，不需要点「生成」。

### 模式三：按目录

**这是 P0-1 的解法，必须按此顺序呈现：**

```
① 读取书签（不依赖文字层）
   有书签 → 显示层级选择 [顶层 ▾] + 章节列表（页码可核对）
   无书签 → ②

② 扫描正文标题（需要文字层）
   有文字层 → 扫描 → 列出候选，标注每个标题的字号倍数（可信度）
   无文字层 → 明确说明：
              「这本书既没有书签，也没有文字层。
                扫描版 PDF 需要 OCR 才能识别标题，当前版本未包含 OCR。」
```

- 「无书签」与「无文字层」是两个**独立**的探测结果，界面分别显示，不再合并成一句话。
- 扫描件的提示里不出现「识别章节」这类会让用户反复点击的入口（不可用就不显示）。

### 8.3 UI 验收的**现实约束（必须提前说明）**

任务书第三阶段要求「页面真实截图」「不得以编译成功代替交互验收」。

- `adb devices` 无设备
- SDK 未安装 emulator 组件（`build-tools/sdk` 只有 build-tools / cmdline-tools / platform-tools / platforms）

三个选项，需你选：

# 附录 A：第一阶段方案的修订（2026-11-08 批准时更正）

## A1 计算错误更正

原文「420 页、每份 50 页 → 8 个文件（最后 22 页）」错误。

**正确：420 ÷ 50 = 8 余 20 → 9 个文件，最后一个 20 页。**

凡 UI 中出现示例数字，一律由代码实时计算并单测覆盖，不在文案里写死。

## A2 「均分 N 份」边界

原文判断「与每份 N 页在 90% 场景等价」不成立，撤回。

两者语义不同：
- **每份 N 页**：固定单份容量，份数由总数推出。
- **均分 N 份**：固定份数，每份容量由总数均摊，需定义余数分配规则。

本次**不实现**，记录为后续独立需求。UI 上不得出现任何暗示可「均分」的入口或文案。

## A3 并发策略改为「待实测」

撤回「文件 >100MB 自动降到 2」的预设规则。改为：

1. 先核查引擎内存模型：每 worker 独立 `PDDocument`（tempFileOnly）+ 主进程堆上限。
2. 以实测数据确定上限，保守默认。
3. 手动配置同样受硬上限约束（不是任意值）。

## A4 页码双编号（新增要求）

PDF 物理页索引与书内印刷页码可能不一致。

- 拆分**只使用 PDF 物理页索引**（0-based 内部、1-based 展示）。
- 存在 Page Labels 时，UI 同时显示「PDF 第 71 页 · 书内 60」，两者不得混用。
- 不存在 Page Labels 时，明确标注「本书无页码标签，按 PDF 页序」。
- 用户输入框接受的永远是 PDF 物理页序号，提示文案要说清。

## A5 文件名冲突的完整范围

预览必须展示**最终落盘文件名**，覆盖四类改写：

1. 批内同名 → `_2` 后缀
2. 非法字符 → `_` 替换
3. 超长 → 按 UTF-8 字节截断（170 B）
4. **输出目录已存在同名文件** → 需查询 SAF 目录，冲突时同样提示

仅检测批内冲突不满足要求。

## A6 部分成功独立实施

原文既称「引擎不变」又要求改失败语义，矛盾已统一为：

**部分成功属于引擎行为变更**，独立成一次改动，独立测试、独立回归，不与 UI 重构混在同一提交。

执行顺序据此调整为：解析/状态 → UI → 部分成功与重试。

## A7 状态恢复边界

`SavedStateHandle` 只保存轻量标识（uri 字符串、模式枚举、规则原文、输出目录 uri、开关布尔）。

**不保存**：`parts` 列表、任务快照、进度数值、`PDDocument` 等大对象。

崩溃/中断后的处理：不信任目录中已存在的同名文件，重试前先按「任务未完成」处理；残缺文件（写一半）必须在启动时按记录清理。
