## 二、测试步骤

1. 安装 APK（覆盖安装即可）。
2. 打开桌面「A1 校验」。
3. 源 PDF 选：
   `/sdcard/Download/BaiduNetdisk/M1racle/老贺/讲义全套/26贺银成实践技能应试指南.pdf`（420 页 / 1,035,745,318 B）
4. 输出目录选一个**新建的空目录**，例如 `/sdcard/Download/实操PDF/A1-20261108-01`。
   - 里面会落下 `L-p001-020.pdf` … `L-p401-420.pdf` 与 `S-p001-020.pdf` … 共 42 个文件，约 2 GB。
5. 渲染像素比对开关：默认**关闭**（PDFBox 自渲染，慢且吃内存，只是抽检）。
   默认关闭时，报告给的是结构级逐页证据；真正的全量像素比对由 PC 侧独立渲染器（poppler）对 L-/S- 产物执行。
6. 点「开始验证」。预计 6～12 分钟（两遍全量拆分 + 逐页指纹 + 对象清单审计）。
7. 结束后屏幕上有摘要，输出目录里会多两个文件：
   - `A1-验证报告-<时间戳>.txt`（人读）
   - `A1-验证报告-<时间戳>.json`（机读，420 页逐页数据）

## 三、报告怎么读

| 章节 | 内容 | 判据 |
| --- | --- | --- |
| 一、加载 | lenient / strict 各自墙钟 + CPU + 页数 | 复现 100 秒 vs 5 秒的量级 |
| 二、拆分 | 两遍拆分各写了多少段、耗时、失败段 | strict 失败段在这里暴露 |
| 三、逐页比对 | 比对页数 / 完全一致 / 差异 / **证据不足** | 差异必须为 0；证据不足必须为 0，否则「一致」不算证据 |
| 四、差异页清单 | 每页差异字段：geometry / content / resources / annots / links / text | 逐条看是哪一类 |
| 五、strict 侧不可解析资源 | 对象号 + 类别/名称 + 引用页 + **是否被 `Do` 实际绘制** | 这是「缺图是否真影响显示」的判据 |
| 六、历史 21 条对象核对 | 1690/2642/3074/…/3156 逐条在本次 strict 解析下的状态 | 与上一轮结论对账 |
| 七、渲染像素 | 仅在开启时出现 | PDFBox 自渲染，一阶参考 |

## 四、需要回传的东西

1. **必需**：`A1-验证报告-*.txt`（+ `*.json` 更好）。
2. **可选但建议**：保留整个输出目录。手机重连后我用 `adb pull` 取 L-/S- 两套产物，
   用 poppler（独立渲染器）做全量逐页像素比对：

   ```bash
   python tools/a1-render-diff.py \
     --lenient <L 产物目录> --strict <S 产物目录> \
     --out output/a1-verify-<日期> --dpi 100
   ```

   输出 `render-diff.csv`（逐页）+ `summary.txt`（汇总）+ `diff/`（差异页）。

## 五、这轮故意没做的

- 没把 `setLenient(false)` 设为全局默认（等 A1 逐页证据）。
- 没改拆分算法、没改 probe、没换引擎。
- 没做「正常 PDF / 损坏 xref / 增量更新 / 对象流 / 加密文件」的扩展测试集——
  那需要另一批合成样本，等 420 页这本的结论落地再排。
